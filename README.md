## 🌟 这是 An_Untitled_ChatAPP！

一款基于 开放式中继协议（Open Relay Protocol） 构想的跨平台聊天软件。

它不想做“另一个微信”或“另一个Telegram”，而是想尝试回答一个问题：

如果聊天软件不是为了“让你更快地回复”，而是为了“让你更自在地连接”，它会是什么样子？

<br>


## 📡 关于“中心化还是去中心化”的真实想法
很多项目一上来就纠结“必须纯去中心化”或者“必须纯中心化”，结果往往陷入两种困境：

* 硬磕纯去中心化（比如 P2P 或区块链）：技术门槛极高，开发几年都未必能稳定跑通，最终用户没等到产品，项目就熄火了。

* 死守纯中心化（传统微信/QQ 模式）：虽然开发简单，但客户端开源就失去了意义——因为服务器是黑盒，用户无法验证你到底有没有偷偷记录聊天记录。

我不想走这两条极端。我真正在乎的只有一件事：用户拥有选择权。

因此，这个项目计划采用 “可插拔中继（Pluggable Relay）” 的开放架构：

  * 开箱即用（默认模式）：
我提供官方的公共中继服务器，所有加密消息通过它暂存和转发。你下载 App 就能立刻用，网络质量由官方保障——跟用微信一样简单。

  * 进阶掌控（高级模式）：
客户端内置“自定义服务器”选项。如果你有技术背景，可以自己部署中继服务端（未来我会开源服务端代码），让所有聊天数据彻底经过你自己的服务器，完全脱离官方控制。

* 协议透明：
客户端与中继之间的通信协议会完整公开。这意味着，哪怕官方服务器某天停运了，只要协议还在，任何人都可以写一个兼容的服务器，让这个 App 继续活下去。

说人话就是：

* 你既不用为了“去中心化”而忍受卡顿和复杂配置，也不用为了“方便”而把全部隐私交给一家公司。默认给你方便，进阶给你自由。

<br>


## 🔐 关于注册：选择权在您的手上！
有些用户希望快速上手，也有的用户希望最大程度保护隐私。

因此，该软件计划提供两种注册方式：

|模式|说明|适合谁|
|---|---|---|
|标准模式|使用手机号或邮箱，快速验证，轻松找到好友。支持密码找回。|大多数普通用户
|匿名模式|仅需昵称，本地生成密钥对，无需任何个人标识符。|隐私敏感者、临时场景用户、跨国用户

两种模式之间可以随时转换（如从匿名模式补绑手机号，用于找回账号或开启通讯录匹配）。

我相信，选择权应该在你手里，而不是由软件来决定你的隐私边界。

## 🛡️ 关于“匿名模式会不会成为可疑人员的天堂？”

这是一个非常现实且无法回避的问题。我的回答是：

“匿名”不等于“无痕”，也不等于“无约束”。

我能看见什么，不能看见什么？

* 能看见：通信元数据，即谁、在什么时间、从哪个 IP、用哪个设备、向哪个一次性 ID 发了消息。这是所有网络通信都无法隐藏的基础信息。

* 看不见：聊天内容（端到端加密，即使是官方中继也无法解密）。

### 如果可疑人员用 VPN 绕过真实 IP 呢？

* 是的，VPN 可以隐藏真实 IP。因此，我的防御体系不依赖 IP 作为唯一证据：

  * 设备指纹锚定：每个匿名身份会与首次激活时的设备硬件指纹软关联。频繁更换 VPN 不会重置你的信用等级，频繁更换设备则会触发“冷静期”限制。

  * 行为成本递增：新匿名账户在初期发送消息存在极轻量的算力验证（PoW），目的是对抗机器人批量注册，对普通人完全无感。

  * 举报-冻结机制：用户可一键举报可疑账户。被多次举报的匿名 ID 会被冻结发送权限，其元数据日志依法封存备查。
 
### 如果可疑人员伪造设备硬件指纹呢？

确实，模拟器/指纹修改工具可以伪造绝大部分硬件参数，但有几样东西难以在低成本下完全伪造，可以通过它们进一步确认：

|可伪造的|难以伪造或伪造代价极高的|
|---|---|
|Android ID、MAC地址（随机化后）、机型、系统版本、屏幕分辨率	|基站信号塔ID（需物理位置移动）、GPS轨迹（需真实运动）、加速度传感器噪声模式（每个设备有微小硬件差异）、电池充放电曲线
|IMEI（新系统已限制读取）|	网络延迟 RTT 模式（物理距离无法瞬间变化）、同一 Wi-Fi 下 ARP 邻居关系（若同局域网有多台设备）

### 能抓到所有可疑人员吗？

不能，而且我不应为此而破坏所有人的隐私。 在端到端加密和无后门的承诺下，如果攻击者使用全新的物理设备 + 高质量住宅代理 + 真人手动模拟行为，我无法（也不应）获取其真实身份。

我能做的，是确保任何受害者只需一键拉黑，即可永久斩断与该攻击者的连接。

我的原则是：让作恶的成本远高于其收益，同时绝对保护普通人的正常通讯。

## ✨ 它将支持的功能

* 🖐️ 手势快捷操作

  * 一拉一滑间即可完成回复、多选消息，甚至在对话中直接创建待办清单或添加日程提醒。

* 🧘 姿势感知反馈

  * 利用手机内置的加速度传感器和陀螺仪，感知你当下的使用姿态，自动切换界面布局：

  * 设备平放（如桌面会议）→ 自动切换为线性对话样式，方便斜眼扫读。

  * 设备倾斜超过 15°（如躺床或行走）→ 界面切换为扇形转轮布局，常用联系人沿拇指弧线排列，单手即可操作。

  * 不需要任何设置菜单，拿起手机的那一刻，界面就是为你此刻的状态而生的。

* 🫧 情绪可视化输入框（实验性）

  * 打字不再只是冷冰冰的文本输入。在你输入时，输入框会基于本地（不上传云端）的语义分析，产生微妙的粒子动效：

    * 输入“哈哈” → 泛起暖色跳跃的小光点。

    * 输入“唉……” → 背景浮现缓慢沉降的淡蓝色波纹。

  * 我认为，文字聊天应该重新拥有“语气”和“温度”。

* 🤖 可选的本地 AI 助手（群组协作者）

  * 你可以选择将一个本地的 AI 助手“拉入”群聊（例如“旅行规划师”或“健康管家”）。

  * 它不依赖云端，完全运行在你的设备上，能听懂群友的讨论，并在需要时提供建议或总结。

  * 所有对话历史仅存于你的设备，AI 不会向任何服务器汇报。

  * 如果你不信任 AI，也可以完全不启用它。这是你的选择，不是强制功能。

🛠 技术选型构想（初步）

为了在“性能”和“可维护性”之间取得平衡，目前倾向于以下组合：

|层级|推荐技术|理由|
|---|---|---|
|核心引擎层（加密、网络协议）|	Rust	|极致性能、内存安全、巨大的后期优化潜力。
|服务端（中继服务器）	|Go|	高并发、开发效率高、生态成熟。
|客户端界面层（跨平台 UI）	|Flutter 或 Kuikly	Flutter |提供绝佳的跨平台 UI 一致性和动画渲染；Kuikly 提供极致轻量的包体积和原生性能。

这套组合的核心思路是：核心逻辑用硬核语言写好，界面层用高效的跨平台框架构建，互不干扰。
